## 4. What the binary actually says (new, verified)

**Component count** — `entity+0x66` is the uint16 count; `+0x64` is `u16 capacity|flags`
(cap = `v & 0x3FFF`, bit15 = buffer not heap-owned). The count occupies the upper u16 of the same
dword, so a 32-bit write destroys it. The array base at `+0x60` is reallocated on grow.
Evidence: `GetComponentByType @0x5200C0`, `AddComponent @0x504F60`, container template `sub_A09AB0`
(`& 0xFFFF3FFF`), `ComponentCache @0x4375D0`. The old `+0x64 & 0xFFFF` read could walk 0xBFFF entries.

**Soldier vs civilian** — `entity+0x9C` is a packed u32: `kind = v & 7`, `role = (v >> 3) & 0x3F`.
`IsSoldier = kind==3 && role==1`, `IsCivilian = (2,2)`. Proven with the game's own predicates
(`sub_73B4B0` guard, `sub_54EC00` civilian) and the role name table `sub_1406C70`
(1=Guard, 2=Civilian, 3=Thief, 5=Mercenary, 19=Animal, 23=Naval). One dword load, no component walk.

**`+0x660` is not a flags word** — `VisualTargetingComponent` is `0xA0` bytes; `+0x660` sits 1,472 B
past the end of it. Image-wide scan finds **zero** RMW/test forms on `[reg+660h]`. `FocusFlags` is
real but at an unproven offset — do not guess it.

**No archetype spawn factory** — creation is `RowSelector`-driven (`0x5FAC00` → `0x5FD520` →
`0x79BC50`); `es.arch` (`bhv+0x14 & 0xFFFF`, `0x35F7` = Spanish soldier) is a tag, not a spawn key.
The plugin holds a selector only for the player. Viable route for spawning a missing enemy: clone a
live local guard (memcpy inherits `+0x114/+0x118`, which a fresh build leaves null).

**The guest's body on the host is a `BhvAssassin` copy of the host player** — `Human`, pad slot,
collision `Disabled(0x29)`, and **no perception registration**. Guards probably cannot see it, which
makes co-op stealth a design question, not a bug.

## 6. What went wrong, and the rule that came out of it

| failure | cost | rule now |
|---|---|---|
| Seats created with a bare `POST /api/session` | inherited a **free model**, timed out for an hour | explicit model in `mkseat.py` |
| That API also ignored `directory` | seats ran in `C:\Users\Administrator` | every charter opens with `cd "<repo>"` |
| Watcher regex `^\s*SEAT` anchored at the start | NET's, IMPL's and RE's fenced reports dropped | regex searched anywhere in the first 600 chars |
| Watcher advanced the mark even when it did not deliver | a dropped report was lost forever | **reports are files; unacked stays in the inbox** |
| Watcher required 45 s of quiet | seats stay `busy`, so finished reports never fired | `bus_watch.py` triggers on file creation |
| Two seats building into a shared `bin/` | NET's tested binary destroyed by IMPL's build | Rule 8: own artefact path |
| Build lock still let one seat build on another's half-finished source | NET's artefact contained IMPL's WIP | Rule 10: commit your own file, the orchestrator builds once |
| Long DM truncated | AI received half a task | one task per message, under ~1200 chars |
| My cleanup filter `AC4Coop.asi.*` matched `AC4Coop.asi` | the active ASI was moved out of the game folder | restore verified: `280D652169D0` back in place |
| Six orphan IDA workers, 871 MB of IDB files written into the game folder | disk + RAM | moved to `ref/ida/` |
| Inherited "proven" facts | hours chasing `+0x660`, the class filter, and the HP lane | every claim re-checked; see `ops/CLAIMS.md` |

The dominant lesson: **the failure mode was never the game, it was silent loss** — of reports, of
artefacts, of facts. Everything that is now reliable is reliable because it leaves a file on disk.

## 9. Incident — the shared IDB lost its function list

At 11:10 the RE seat opened the shared database from a second process with auto-analysis off, and the
close persisted a DB without function records: **128,610 -> 964**. Instruction bytes, names and
comments were intact; only boundaries were gone.

Recovery (verified): 45,059 functions re-added from `RE-AC4/symbols/functions.jsonl` +
`functions_v2.jsonl` (674 already present, 131 failed), DB saved. Probes confirm correct bounds
(`sub_54EC00` 31 B, `sub_67B2A0` 316 B, `sub_133F630` 297 B …). The ~95k *unnamed* boundaries are
not restored; they can be added on demand (`ops/tools/restore_funcs.py --add <addr>`), which costs
about 0.01 s each.

Rules added: one process per DB; never `close_database(save=True)` after a no-analysis open;
snapshot `backups/idb/` (452 MB) before any write.
